# Rollout Tracker — Design

**Date:** 2026-08-24
**Status:** Approved, implementing
**Scope:** New screen for tracking a customer site rollout against its SOW.
First customer: Landmark.

---

## 1. Why

Landmark's rollout is tracked in a spreadsheet of counts — a number per country
per site category, for what was scoped and what is done. Checking that sheet
surfaced the problem with counting by hand:

| Country | SOW | Done | What the totals were hiding |
|---|---|---|---|
| KSA | 204 | 204 | +5 stores, −5 offices, −4 warehouses, **+4 DC/DR never scoped** |
| Jordan | 8 | **9** | one site completed that was never in the SOW |
| Bahrain | 9 | 9 | +1 store, −1 office |

KSA reads as a clean 204 of 204 with zero remaining while four of its six
categories are wrong. The bottom line reconciles, so nobody looks at the
columns. That is the failure mode this design exists to remove.

## 2. The core decision

**Sites are rows. Every count is a `COUNT`.**

Nothing in the report is typed. SOW, Completed and Remaining are all derived
from the site rows, so the categories cannot disagree with the totals — the
categories *are* the rows.

`in_sow` is what catches Jordan: a site completed that was never scoped is a row
with `in_sow = false`, so instead of an unexplained `-1` the report states
"1 completed outside SOW".

`Cloud` stays a valid country value even though it is also a site type, because
the source sheet uses it that way and the export must reproduce that format
rather than a tidier one.

## 3. Schema

```sql
create table public.rollout_projects (
  id            bigint generated by default as identity primary key,
  name          text not null,
  customer_name text,
  sow_date      date,
  is_archived   boolean not null default false,
  created_at    timestamptz not null default now()
);

create table public.rollout_sites (
  id           bigint generated by default as identity primary key,
  project_id   bigint not null references public.rollout_projects(id) on delete cascade,
  site_name    text not null,
  country      text not null,
  city         text,
  site_type    text not null
               check (site_type in ('store','office','warehouse','interlinked','dc_dr','cloud')),
  in_sow       boolean not null default true,
  status       text not null default 'pending' check (status in ('pending','done')),
  completed_on date,
  mpls_configured boolean not null default false,
  mpls_on      date,
  notes        text,
  created_at   timestamptz not null default now(),
  updated_at   timestamptz not null default now(),
  updated_by   text
);
```

`site_type` values are stored lowercase with underscores, matching the
`unified_sessions.session_type` convention already in this codebase (a CHECK
constraint there rejects capitalised values, and the same trap applies here).

**Indexes:** `(project_id, country)`, `(project_id, status)`.

**Uniqueness:** `unique (project_id, site_name, site_type)` so a re-run of the
import cannot silently duplicate a site.

## 4. Permissions

| Action | Who |
|---|---|
| Read sites and reports | any authenticated user |
| Mark a site done / not done, set MPLS | any authenticated user |
| Add, edit, delete a site; import; edit the SOW baseline | managers only |

Rationale: the engineers doing the rollout are the ones who know a site is
finished, so day-to-day updates must be frictionless. The SOW baseline is the
thing that must not move by accident, so it is manager-gated.

`updated_by` is stamped with `current_employee_name()` on write so a status
change is attributable.

## 5. Screens

Sidebar gets a new group **Rollout Tracker**, distinct from the existing
**Project Tracker** (which tracks engagements, not sites). Under it, one entry
per project — **Landmark** today.

Three sub-tabs:

**Overview** — the report, computed live:
- SOW block: country × site type, with totals
- Completed block: same shape, plus Completed and Remaining columns
- Per-country city breakdown for any country that has cities (KSA and UAE today)
- MPLS Config block
- An explicit "completed outside SOW" line when any exist

**Sites** — the rows. Filter by country, type, status, MPLS. Search by name.
One click to toggle a site done. Managers additionally get add / edit / delete.

**Import** — paste CSV, map columns on screen, preview, then commit. Column
mapping rather than a fixed format, because the source file's headers are not
known in advance and guessing them is how imports fail on first contact.

## 6. Export

One button on Overview producing an `.xlsx` that reproduces the source sheet's
layout, in this order:

1. SOW table
2. `COMPLETED till Today-DD/MM/YYYY`
3. Per-country city breakdowns
4. `MPLS Config Breakdown`

Filename `landmark-rollout-YYYY-MM-DD.xlsx`. Uses the SheetJS lazy-load the app
already has for Full Backup — no new dependency.

## 7. What this is not

- **Not a replacement for Project Tracker.** That tracks engagements through
  delivery phases. This tracks physical sites against a scope of work.
- **No per-site workflow stages.** One status plus an MPLS flag, as chosen.
  If stages are wanted later they are a new table, not more columns here.
- **No scheduling, assignment or effort tracking.** Sessions already do that.

## 8. Open items
