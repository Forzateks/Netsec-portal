# Professional Services Deals — Activity Log

**Date:** 2026-07-28
**Status:** Approved, pending implementation
**Area:** New Supabase table `ps_deal_activity_log`; `js/features/ps-deals.js`; `index.html` (Professional Services sidebar entry + new sub-tab markup); `js/core/navigation.js`; `js/features/dashboard.js` (`BACKUP_TABLES`); `docs/schema.sql`

## Problem

Professional Services deals (`Customers & Deals → Professional Services`) have no history, same gap AMC Contracts had before v152: an edit to a deal's value, status, or any other field simply overwrites the old value with no record of who changed what or when, and archiving/restoring/permanently deleting a deal leaves no trace.

## Goal

Apply the same audit-log capability just shipped for AMC Contracts (v152) to PS Deals: every create, top-level field edit, archive, restore, and permanent delete is recorded (who, when, per-field old→new diff for edits), viewable in a new "Activity Log" sidebar sub-tab under Professional Services.

## Non-goals

- **Milestones are out of scope** (confirmed with the user). `ps_milestones` rows (percentage splits, payment received, per-milestone status) are not tracked — only the parent deal's own top-level fields. Matches how the AMC log already excludes its own relational concept (linked engagements).
- No per-deal "History" panel in the deal modal — Activity Log is a single company-wide view, same placement decision as AMC.
- No new `BACKEND.md` section — same precedent-following decision as AMC (no table added since `kb_articles` has one; `docs/schema.sql` is the real source of truth in practice).
- No retroactive backfill — starts recording from the moment this ships.
- No UI to filter/search the log by deal or manager — matches the AMC log's scope (and Inventory's, which it was modeled on).

## Design

### 1. New table: `ps_deal_activity_log`

```sql
CREATE TABLE public.ps_deal_activity_log (
  id bigint GENERATED BY DEFAULT AS IDENTITY NOT NULL,
  deal_id bigint,
  client_name text,
  changed_by text NOT NULL,
  action text NOT NULL,
  field_changes jsonb,
  changed_at timestamptz DEFAULT now()
);

ALTER TABLE public.ps_deal_activity_log
  ADD CONSTRAINT ps_deal_activity_log_pkey PRIMARY KEY (id);

ALTER TABLE public.ps_deal_activity_log ENABLE ROW LEVEL SECURITY;

CREATE POLICY ps_deal_activity_log_select_manager
  ON public.ps_deal_activity_log FOR SELECT TO authenticated
  USING (is_manager_user());
CREATE POLICY ps_deal_activity_log_insert_manager
  ON public.ps_deal_activity_log FOR INSERT TO authenticated
  WITH CHECK (is_manager_user() AND changed_by = current_employee_name());
```

Two deliberate departures from a byte-for-byte copy of `amc_contract_activity_log`, both correcting for things learned building that feature:

- **`SELECT` is manager-gated here**, not open to any authenticated user. `amc_contracts` itself has an open-read policy (`amc_contracts_select_authenticated ... USING (true)`), which is why its log's `SELECT` is open too. `ps_deals` has no such policy — it's `FOR ALL ... USING (is_manager_user())`, fully closed to non-managers. The log must match its parent table's actual access model, not AMC's.
- **`INSERT` binds `changed_by = current_employee_name()` from the start.** AMC's log shipped without this and needed a follow-up fix after the final review found `changed_by`/`changed_at` were fully client-controlled (a manager could author a log row attributing an action to someone else). Building it in from the start here avoids repeating that gap.

No foreign key on `deal_id` — same reasoning as AMC: a permanently-deleted deal's history must survive the delete. No CHECK constraint on `action` — matches both `inventory_activity_log` and `amc_contract_activity_log`, entirely app-controlled values.

### 2. Logging hook points in `js/features/ps-deals.js`

Same four functions, same five actions:

| Function | Action logged | field_changes |
|---|---|---|
| `savePsDeal()` — insert path (new deal) | `created` | full payload |
| `savePsDeal()` — update path (existing deal) | `updated` | only fields that changed, `{from, to}` — only inserted if at least one field actually changed |
| `archivePsDealFromModal()` | `archived` | `{}` |
| `restorePsDeal()` | `restored` | `{}` |
| `permanentlyDeletePsDeal()` | `permanently_deleted` | `{}` — logged **before** the actual `DELETE`, same ordering as AMC/Inventory |

Tracked fields for the `updated` diff — every top-level column on `ps_deals` except metadata (`id`, `created_by`, `created_at`, `updated_at`, `is_archived`, `archived_at`) and the milestones relationship (out of scope, §Non-goals):

| Column | Label |
|---|---|
| client_name | Client |
| partner | Partner |
| region | Region |
| mode | Mode |
| vendor | Vendor |
| quoted_year | Quoted Year |
| quoted_month | Quoted Month |
| awarded_year | Awarded Year |
| man_days | Man Days |
| ps_quoted_tech_usd | PS Tech (USD) |
| ps_quoted_sales_usd | PS Sales (USD) |
| final_ps_value_usd | Final PS Value (USD) |
| status | Status |
| consulted_with_tech | Consulted With (Tech) |
| remarks | Remarks |
| linked_engagement_id | Linked Engagement |

`linked_engagement_id` is logged as the raw numeric id (no name lookup/resolution) — keeps this a direct mirror of the AMC pattern rather than introducing new complexity; a manager reading "Linked Engagement: 42 → 57" can cross-reference if needed.

### 3. UI restructure: Professional Services becomes a two-tab sidebar group

Today `Professional Services` is a single flat `sidebar-item` (`onclick="showScreen('psdeals')"`), same shape AMC Contracts had before v152. Same restructure:

- **Deals** — today's existing list/filters/revenue-chart/modal experience, unchanged, wrapped in a new `#pstab-deals` container.
- **Activity Log** (new) — one table across every deal, newest first, columns: Date, Client, Action, Changed By, Changes — modeled directly on `loadAMCActivityLog()`.

New `showPsDealsTab(tab)` (mirrors `showAMCTab(tab)`) and `loadPsDealActivityLog()` (mirrors `loadAMCActivityLog()`). `js/core/navigation.js`'s `showScreen()` (currently `if (name==='psdeals') loadPsDeals();`) and `navigateSub()` both need the same one-line addition AMC already has.

Note: the existing "Revenue by Year" chart (`#ps-revenue-chart`, v150) lives inside the page today, outside the filter bar — it moves into `#pstab-deals` along with everything else already in that screen, unchanged in behavior (it's independent of filters/tabs already, per its own v150 design).

### 4. Sync discipline

- `docs/schema.sql` — new table, PK, RLS enable, 2 policies, in the same place `ps_deals`/`ps_milestones` already appear.
- `js/features/dashboard.js` `BACKUP_TABLES` — add `{ table:'ps_deal_activity_log', sheet:'PS Deal Activity Log', idCol:'id' }` after `ps_milestones`, before `unified_sessions`.
- `docs/disaster-recovery.md` — add the new table to the restore-order list (table count 29→30) and the Step 7 verify-counts SQL. The AMC plan missed this and it surfaced as an Important finding in that feature's final review; this plan includes it from the start instead of repeating the gap.
- No `BACKEND.md` section (see Non-goals — same precedent AMC followed).

## Data flow summary

```
savePsDeal() / archivePsDealFromModal() / restorePsDeal() /
permanentlyDeletePsDeal()
  → existing ps_deals mutation (unchanged)
  → NEW: sb.from('ps_deal_activity_log').insert({...})

navigateSub('psdeals', tab) / showScreen('psdeals')
  → showPsDealsTab(tab)                    // NEW, mirrors showAMCTab
      tab === 'deals' → loadPsDeals()                    // unchanged (incl. revenue chart)
      tab === 'log'   → loadPsDealActivityLog()          // NEW
          → sb.from('ps_deal_activity_log').select('*').order('changed_at', desc)
          → renders table, mirrors loadAMCActivityLog()
```

## Testing

Manual — no automated tests in this repo (`docs/testing/`). Same scenario set as the AMC plan, adapted:

1. Create a new deal → one `created` log row with the full initial field set.
2. Edit only Status on an existing deal → one `updated` row, `field_changes` contains only `"Status": {from, to}`.
3. Edit three fields at once (e.g. Final PS Value, Status, Remarks) → one `updated` row with exactly those three fields diffed.
4. Save a deal with no actual field changes → no log row written.
5. Archive a deal → `archived` row, no diff. Restore → `restored` row. Permanently delete → `permanently_deleted` row present in the log after the deal itself is gone (no FK cascade).
6. Activity Log lists entries newest-first, across every deal.
7. Non-manager (employee): the whole Professional Services sidebar group (both sub-items) stays hidden — pre-existing manager-only gating, unaffected. Additionally: a manager can read the log (`SELECT` policy), an employee's direct API access is denied by RLS (not just UI-hidden) — this is the one behavior AMC's log doesn't have (its own `SELECT` is open to all authenticated).
8. Full Backup includes a "PS Deal Activity Log" sheet.
9. Switching between Deals and Activity Log sub-tabs preserves the Deals view's filter state; the Revenue by Year chart still renders correctly inside the Deals tab, unaffected by the restructuring.
10. `docs/disaster-recovery.md`'s Step 7 verify-counts SQL includes `ps_deal_activity_log` and returns a correct count.
11. Attempt (via direct API/SQL, not through the UI) to `INSERT` a log row with `changed_by` set to a different employee's name while authenticated as a manager whose `current_employee_name()` doesn't match — confirm RLS rejects it. This directly exercises the "built in from the start" hardening (§1) rather than deferring it to a follow-up fix like AMC needed.
