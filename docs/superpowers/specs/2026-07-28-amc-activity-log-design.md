# AMC Contracts — Activity Log

**Date:** 2026-07-28
**Status:** Approved, pending implementation
**Area:** New Supabase table `amc_contract_activity_log`; `js/features/amc-contracts.js`; `index.html` (AMC Contracts sidebar entry + new sub-tab markup); `js/core/navigation.js`; `js/features/dashboard.js` (`BACKUP_TABLES`, `_sqlEscape`); `docs/schema.sql`; `BACKEND.md`

## Problem

AMC Contracts (`Customers & Deals → AMC Contracts`) has no history. When a
manager edits a contract's value, dates, client, or any other field, the old
value is simply overwritten with no record of what changed, who changed it,
or when — and archiving, restoring, or permanently deleting a contract
leaves no trace either. Inventory already solved exactly this problem for
devices (`inventory_activity_log` + its "Activity Log" sidebar view); AMC
Contracts needs the same capability.

## Goal

Every create, field edit, archive, restore, and permanent delete on an AMC
contract is recorded with who did it, when, and (for edits) a per-field
old→new diff. Viewable in a new "Activity Log" sidebar sub-item under AMC
Contracts, mirroring Inventory's existing Activity Log view.

## Non-goals

- Does not track changes to linked engagements (the checkbox list in the
  contract modal) — that's a relational many-to-many concept, not a scalar
  field diff. Matches Inventory's existing scope, which also only tracks
  scalar field changes, not relational links.
- Does not add a per-contract "History" section to the Detail modal — the
  approved design is a single company-wide Activity Log view only (per the
  placement decision below).
- No retroactive backfill — the log starts recording from the moment this
  ships; contracts' prior edit history (before this feature existed) is not
  reconstructable and isn't attempted.
- No UI to filter/search the log by contract or manager in this pass —
  Inventory's existing Activity Log view doesn't have that either; if it's
  wanted later, it's a separate small addition on top of this table.

## Design

### 1. New table: `amc_contract_activity_log`

Mirrors `inventory_activity_log`'s exact shape and conventions:

```sql
CREATE TABLE public.amc_contract_activity_log (
  id bigint GENERATED BY DEFAULT AS IDENTITY NOT NULL,
  contract_id bigint,
  customer_name text,
  changed_by text NOT NULL,
  action text NOT NULL,
  field_changes jsonb,
  changed_at timestamptz DEFAULT now()
);

ALTER TABLE public.amc_contract_activity_log
  ADD CONSTRAINT amc_contract_activity_log_pkey PRIMARY KEY (id);

ALTER TABLE public.amc_contract_activity_log ENABLE ROW LEVEL SECURITY;

CREATE POLICY amc_contract_activity_log_select_authenticated
  ON public.amc_contract_activity_log FOR SELECT TO authenticated USING (true);
CREATE POLICY amc_contract_activity_log_insert_manager
  ON public.amc_contract_activity_log FOR INSERT TO authenticated
  WITH CHECK (is_manager_user());
```

- `contract_id` has **no foreign key** — same reasoning as `device_id` on
  `inventory_activity_log`: a permanently-deleted contract's history must
  survive the delete, not cascade away with it.
- `action` values: `created`, `updated`, `archived`, `restored`,
  `permanently_deleted`. No CHECK constraint — `inventory_activity_log.action`
  doesn't have one either (matches existing precedent; the values are
  entirely app-controlled, this table has no direct user-input surface).
- `field_changes` shape for `updated`: `{ "Field Label": { "from": ..., "to": ... } }`
  — identical structure to Inventory's, so the rendering code can follow the
  same pattern. For `created`, it's the full initial field set (unlabeled
  raw payload, matching Inventory's `created` action — note Inventory's own
  log viewer doesn't actually render this for `created`/`deleted` rows, only
  for `updated`; this spec keeps that same behavior rather than "fixing" it,
  since it's an existing, deliberate-enough convention not worth diverging
  from in a mirrored feature).
- **Deliberately stricter than `inventory_activity_log`'s current RLS**: this
  table gets no UPDATE or DELETE policy at all (Inventory's existing policy
  is a single blanket `FOR ALL USING (auth.role()='authenticated')`, which —
  despite `BACKEND.md` describing that table as "append-only" — technically
  permits authenticated users to modify or delete rows in it). Omitting
  UPDATE/DELETE policies here means RLS denies both by default for everyone,
  making this log genuinely tamper-proof. This is a one-line policy
  difference from the mirrored precedent, not a new pattern.
- INSERT is manager-only (`is_manager_user()`), matching `amc_contracts`
  itself (`amc_contracts_insert_manager`/`_update_manager`/`_delete_manager`)
  rather than Inventory's looser any-authenticated-can-write policy — AMC
  Contracts is already a fully manager-gated screen, so its log should be too.

### 2. Logging hook points in `js/features/amc-contracts.js`

Five existing functions each gain one `sb.from('amc_contract_activity_log').insert(...)` call:

| Function | Action logged | field_changes |
|---|---|---|
| `saveAMCContract()` — insert path (new contract) | `created` | full payload |
| `saveAMCContract()` — update path (existing contract) | `updated` | only fields that changed, `{from, to}` — only inserted if at least one field actually changed |
| `archiveAMCContract()` | `archived` | `{}` |
| `restoreAMCContract()` | `restored` | `{}` |
| `permanentlyDeleteAMCContract()` | `permanently_deleted` | `{}` — logged **before** the actual `DELETE`, same ordering as Inventory's `deleteDevice()` |

Tracked fields for the `updated` diff (labels shown in the log view):

| Column | Label |
|---|---|
| customer_name | Client |
| partner | Partner |
| region | Region |
| vendor | Vendor |
| git_sales_order | GIT Sales Order |
| amc_value_usd | AMC Value (USD) |
| amc_start_date | Start Date |
| amc_end_date | End Date |
| booking_year | Booking Year |
| notes | Notes |

### 3. UI restructure: AMC Contracts becomes a two-tab sidebar group

Today `AMC Contracts` is a single flat `sidebar-item` (`onclick="showScreen('amc')"`)
with no sub-tabs. This changes it to an expandable `sidebar-group` — the
exact same structural pattern Inventory already uses
(`sbg-inventory` / `has-children` / `sidebar-submenu` / `sidebar-subitem`):

- **Contracts** — today's existing list/filters/detail/modal experience,
  completely unchanged in behavior. All existing element ids
  (`amc-content`, `amc-total-card`, filter bar, etc.) stay exactly as they
  are, just wrapped in a new `#amctab-contracts` container div.
- **Activity Log** (new) — one table across every contract, newest first,
  columns: Date (relative time), Client, Action (colored badge + icon),
  Changed By, Changes (from→to diff list) — directly modeled on
  `loadActivityLog()` in `js/features/inventory.js`.

A new `showAMCTab(tab)` function (mirroring `showInventoryTab(tab)` exactly)
toggles the two containers' visibility, updates the active sidebar sub-item,
and triggers the right load function (`loadAMCContracts()` for `contracts`,
a new `loadAMCActivityLog()` for `log`). `js/core/navigation.js`'s
`showScreen()` (currently `if (name==='amc') loadAMCContracts();`) and
`navigateSub()` (currently missing an `amc` branch) both need the same
one-line addition Inventory already has for its own screen name.

### 4. Sync discipline — required alongside the schema change

Per this project's conventions (`CLAUDE.md` §9), a new table means all of
the following ship in the same change, not as an afterthought:

- `docs/schema.sql` — add the new `CREATE TABLE`, PK constraint, RLS
  enable, and the two policies, in the same place `amc_contracts` and
  `inventory_activity_log` already appear.
- `BACKEND.md` — new numbered table section, same doc style as the existing
  `### 9. inventory_activity_log` entry, including the "SQL to run" block.
- `js/features/dashboard.js` `BACKUP_TABLES` — add
  `{ table:'amc_contract_activity_log', sheet:'AMC Contract Activity Log', idCol:'id' }`
  in FK-dependency order (after `amc_contract_engagements`, alongside where
  `inventory_activity_log` sits relative to `inventory`), so Full Backup
  and the SQL data dump both include it.
- `js/features/dashboard.js` `_sqlEscape()` — its comment currently claims
  "only inventory_activity_log.field_changes" is a jsonb column in the
  schema; that comment becomes stale once this table ships (the code itself
  needs no change — the `typeof v === 'object'` branch already handles any
  jsonb column generically — just the comment needs updating to mention
  both tables).

### 5. Version trio + release notes

Standard `CLAUDE.md` §5 requirement — this is a visible new sidebar
sub-item, so `sw.js`/`js/core/init.js`/`index.html` Sentry release/
`data/whats-new.json` all bump together.

## Data flow summary

```
saveAMCContract() / archiveAMCContract() / restoreAMCContract() /
permanentlyDeleteAMCContract()
  → existing amc_contracts mutation (unchanged)
  → NEW: sb.from('amc_contract_activity_log').insert({...})

navigateSub('amc', tab) / showScreen('amc')
  → showAMCTab(tab)                      // NEW, mirrors showInventoryTab
      tab === 'contracts' → loadAMCContracts()          // unchanged
      tab === 'log'       → loadAMCActivityLog()        // NEW
          → sb.from('amc_contract_activity_log').select('*').order('changed_at', desc)
          → renders table, mirrors inventory.js's loadActivityLog()
```

## Testing

Manual — no automated tests in this repo (`docs/testing/`).

1. Create a new contract → one `created` log row with the full initial
   field set appears in Activity Log.
2. Edit only the AMC Value on an existing contract → one `updated` row
   appears, `field_changes` contains only `"AMC Value (USD)": {from, to}` —
   no other fields listed.
3. Edit three fields at once (e.g. Value, End Date, Notes) → one `updated`
   row with exactly those three fields diffed.
4. Save a contract with no actual field changes (open Edit, change nothing,
   Save) → no log row is written (matches Inventory's `if
   (Object.keys(changes).length > 0)` guard).
5. Archive a contract → one `archived` row, no field diff. Restore it → one
   `restored` row. Permanently delete an archived contract → one
   `permanently_deleted` row is present in the log **after** the contract
   itself is gone from `amc_contracts` (proving there's no FK cascade
   wiping the log entry).
6. Activity Log lists entries newest-first, across every contract (not
   filtered to one).
7. Non-manager (employee) view: AMC Contracts sidebar item — and both its
   sub-items — stay hidden entirely (existing manager-only gating,
   unaffected by this change).
8. Full Backup (Admin Tools) includes an "AMC Contract Activity Log" sheet
   in the exported .xlsx and the corresponding table in the .sql dump.
9. Switching between the Contracts and Activity Log sub-tabs preserves each
   view's own state correctly (e.g. leaving Contracts mid-filter and coming
   back doesn't lose the filter; Activity Log always shows the full,
   unfiltered list).
